# 物证档案局（Evidence Bureau）产品需求文档

> 文档状态：第一版基线
>
> 产品版本：Chapter 01 / MVP
>
> 首发案件：《消失的住客》
>
> 目标平台：桌面浏览器
>
> 首发语言：简体中文

## 1. 产品摘要

《物证档案局》是一款以三维物证调查为核心的网页推理解谜游戏。玩家进入一套冷峻的数字调查终端，自由旋转和检查物证，使用白光、侧光、紫外、线框和测量等工具发现痕迹，再把物证、证词和中间结论连接成一条可验证的证据链。

第一版不是 3D 模型生成器，也不是用户创作平台。它要交付一宗完整、精致、可公开试玩的案件，用实际体验验证以下核心命题：

> 玩家是否愿意仔细观察一个 3D 物体，并从空间结构与细微痕迹中获得真正的推理乐趣？

Step1X-3D 是幕后资产生产流程的一环：开发者使用照片生成物证几何草模，经过清理、减面、压缩和热点标注后，作为固定游戏资源发布。玩家不会在游戏过程中等待模型生成，线上游戏也不依赖 GPU 推理服务。

## 2. 产品定位

### 2.1 一句话介绍

旋转、扫描并检查三维物证，把沉默的物品连接成能够证明真相的证据链。

### 2.2 中文名与英文名

```text
中文名：物证档案局
英文名：Evidence Bureau
宣传语：每一件物品，都藏着一个答案。
```

### 2.3 核心差异

- 物证不是普通图片或文字卡片，而是可自由观察的 3D 对象。
- 线索不会直接显示为发光按钮；玩家必须选择正确工具、角度和观察距离。
- 最终答案不是单项选择题，而是由玩家构建的证据链。
- 视觉重点是几何、结构与扫描数据，不依赖写实纹理。
- 案件真相唯一、证据闭环，但调查完整度会影响评级与附录解锁。

## 3. 第一版目标

### 3.1 产品目标

1. 提供一宗 25～40 分钟可通关的完整案件。
2. 支持三件可独立检查的 3D 核心物证。
3. 让玩家通过五种调查工具发现至少 12 条有效线索。
4. 让玩家在推理板上构建至少三条中间结论和一条最终证据链。
5. 在普通近五年笔记本上保持可接受的加载速度和交互帧率。
6. 不要求注册，不依赖后端，打开链接即可游玩并自动保存。
7. 提供开发者可视化标注模式，为模型配置热点和触发条件。

### 3.2 成功标准

第一版视为成功，需要同时满足：

- 新玩家不看开发说明即可开始调查。
- 至少 80% 的核心线索能在不使用第三级提示的情况下被测试玩家发现。
- 测试玩家能够复述“空间路径、时间空档、通行工具”三条核心逻辑。
- 完整通关不存在只能靠猜测的必选节点。
- 案件从首屏进入可操作状态不超过 5 秒（目标网络与设备条件下）。
- 调查场景在普通集成显卡设备上目标 60 FPS，最低不持续低于 30 FPS。
- 刷新页面或关闭浏览器后，调查进度可正确恢复。
- 断网后，已经加载完成的当前调查页面不会立即丢失进度。

## 4. 非目标

第一版明确不做：

- 玩家实时上传图片并生成 3D 模型。
- 用户账号、云存档、排行榜或付费系统。
- 用户创作、审核和发布案件的平台。
- 多人协作、实时聊天或在线联机。
- 开放世界、角色移动或完整三维房间漫游。
- 写实电影级纹理与光线追踪。
- AI 自动判断自由文本推理。
- 移动端首发体验保证。
- 多结局对应多个客观真相。
- 防止玩家通过浏览器开发者工具查看静态案件答案。

## 5. 目标用户

### 5.1 核心用户

- 喜欢密室、刑侦、档案和逻辑推理的玩家。
- 喜欢《Her Story》《Return of the Obra Dinn》或异常档案氛围的用户。
- 对 3D 交互、数字扫描和视觉化调查感兴趣的桌面网页用户。

### 5.2 使用条件

- 桌面 Chrome、Edge、Firefox 或 Safari 的现代版本。
- 鼠标或触控板；键盘用于快捷键和无障碍操作。
- 支持 WebGL 2 的设备。
- 首发文案为简体中文。

## 6. 第一宗案件：《消失的住客》

### 6.1 故事前提

一名住客在房门从内部锁住、走廊监控无人进出的情况下消失。房内没有明显打斗痕迹，窗户也无法通行。旅馆提交的现场记录看似完整，却有三件物品无法解释：一张位置异常的桌子、一台损坏的旧相机，以及一把不属于房门的黄铜钥匙。

案件表面带有超自然色彩，但最终必须能够被现实证据完整解释。

### 6.2 客观真相

住客发现自己被长期监视，于是主动设计了一场密室失踪：

1. 他移动桌子，打开并重新遮盖旧建筑的检修通道。
2. 他利用旧相机的延时机构和预先安排的影像，制造自己在更晚时间仍留在房内的假象。
3. 黄铜钥匙用于打开检修设施，而不是房门。
4. 他通过检修通道离开，房门仍保持从内部锁住的表象。

第一章回答“他如何消失”，但不完全回答“谁在监视他”，后者作为后续章节的主线钩子。

### 6.3 三件核心 3D 物证

#### A. 被移动过的桌子

承担空间证据：

- 桌腿底部存在与房间地面不一致的灰尘和新鲜磨痕。
- 桌面与墙面碰撞形成的缺口方向和现场照片不一致。
- 线框模式可观察到桌板下方不合理的遮挡或固定结构。
- 测量结果表明桌子移动后恰好能够覆盖检修口。

#### B. 损坏的旧相机

承担时间证据：

- 机械计数器与登记的照片数量不一致。
- 侧光能显示快门拨盘近期被强行调整的痕迹。
- 紫外模式可发现被擦除的标记。
- 反光或照片编号揭示所谓“失踪后影像”实际提前拍摄。

#### C. 黄铜钥匙

承担通行工具证据：

- 齿形与客房门锁明显不匹配。
- 磨损集中在钥匙侧缘，符合老式检修锁结构。
- 表面残留与检修通道一致的油脂或矿物粉尘。
- 隐蔽编号可与建筑旧档案中的设施编号对应。

### 6.4 辅助材料

- 现场照片 3～5 张。
- 走廊监控时间摘要。
- 旅馆管理员、清洁人员、隔壁住客的证词。
- 建筑旧平面图或检修记录。
- 入住登记、维修单和相机冲洗记录。
- 一份可选隐藏档案，用于指向监视者身份。

## 7. 核心游戏循环

```text
阅读案件简报
  → 选择一件物证
  → 自由旋转、缩放与检查
  → 切换调查工具
  → 满足观察条件并记录线索
  → 阅读证词和档案
  → 在推理板连接证据
  → 形成中间结论
  → 提交最终证据链
  → 查看结案报告与调查评级
```

玩家可以在物证调查、档案阅读和推理板之间自由切换。除教学阶段外，不强制固定调查顺序；但某些深层线索可以要求先发现前置线索。

## 8. 功能需求

### 8.1 案件入口与简报

- 展示案件编号、标题、状态、地点和简短摘要。
- 首次进入提供不超过 90 秒的交互教学。
- 支持“开始调查”和“继续调查”。
- 已通关后支持重新调查和重置进度。
- 明确提示最佳体验为桌面浏览器和鼠标。

### 8.2 物证库

- 展示三件物证的档案卡片、编号和当前调查进度。
- 未检查、调查中、关键线索完整三种状态必须可区分。
- 物证模型按需加载，一次只保留当前高精度模型。
- 模型加载期间显示进度和案件内合理的扫描提示。
- 加载失败时允许重试，并提供低清占位图和文字档案入口。

### 8.3 3D 物证查看器

- 鼠标左键拖动旋转，滚轮缩放，右键或组合键平移。
- 提供“重置视角”和“聚焦物证”操作。
- 限制过近、过远和穿入模型内部的异常视角。
- 支持热点区域的射线检测，但默认不渲染热点标识。
- 支持物证局部聚焦，线索确认后可快速返回对应区域。
- 支持键盘操作，并为主要操作提供可见焦点状态。
- 在 WebGL 不可用时提供明确说明，而不是空白页面。

### 8.4 调查工具

第一版包含五种工具：

1. **白光**：默认模式，观察整体轮廓、破损和普通标记。
2. **侧光**：改变低角度光照，突出划痕、凹痕和表面起伏。
3. **紫外**：以非写实扫描图层显示荧光、擦除痕迹和残留物。
4. **线框**：展示拓扑与结构异常，辅助发现夹层和拼接。
5. **测量**：选择两个表面点，显示距离；必要时支持角度测量。

工具不是装饰效果。至少一条核心线索必须要求正确工具才能确认。

### 8.5 线索发现判定

一条 3D 线索可以同时要求：

- 当前选择指定调查工具。
- 镜头与热点表面法线的夹角处于允许范围。
- 相机距离或屏幕占比达到阈值。
- 光标或视线在区域内停留指定时间。
- 已发现前置线索。

满足条件时先显示“异常信号”，玩家确认后才将其加入档案。不得仅靠快速乱点遍历全部热点。

### 8.6 线索档案

- 每条线索包含标题、描述、来源、截图或示意图、标签和发现时间。
- 区分核心线索、辅助线索和隐藏线索。
- 支持从线索卡返回物证对应观察区域。
- 线索文本必须描述观察事实，不直接替玩家给出最终结论。
- 新线索必须有视觉与可选音效反馈，但不应长时间打断操作。

### 8.7 人物证词与文档

- 证词以可逐段引用的陈述单元保存，而不是一整页不可操作文本。
- 玩家可以把一段证词钉到推理板。
- 文档中的时间、编号和关键实体可高亮，但不能自动标明矛盾。
- 所有音频信息必须有字幕或文字等价内容；第一版允许完全不使用配音。

### 8.8 证据链推理板

- 节点类型包括物证线索、证词、档案事实、中间结论和最终结论。
- 玩家通过拖线建立关系，至少支持“支持”“矛盾”“因果”“对应”四种关系。
- 合法组合形成中间结论；不合法组合提供温和反馈，不直接揭示答案。
- 最终提交必须覆盖空间路径、时间空档和通行工具三条核心链路。
- 提交失败时指出缺失的逻辑类别，不直接给出正确节点。
- 推理板布局和连接状态随存档保存。

### 8.9 分级提示

每个关键阻塞点提供三级主动提示：

1. 提示调查方向。
2. 提示应使用的工具或相关档案。
3. 指出具体物证区域或所需证据组合。

玩家主动申请提示；系统不自动弹出。提示使用次数影响调查评级，但不得阻止通关。

### 8.10 结案与评级

案件只有一个客观真相。通关后根据以下维度给出 `C/B/A/S` 评级：

- 核心线索完成度。
- 可选和隐藏线索完成度。
- 最终证据链准确度。
- 提示使用次数。
- 错误提交次数。
- 调查用时（低权重，不鼓励仓促游玩）。

所有评级都能看到主结局。高评级解锁完整案件附录、隐藏档案和下一章伏笔，不改变客观真相。

### 8.11 本地存档

- 无需账号，自动保存在浏览器本地。
- 保存已读简报、物证状态、已发现线索、提示次数、推理板、设置和评级。
- 存档必须带版本号并支持迁移或安全重置。
- 损坏存档不得使页面无法打开；应允许导出、重置或恢复到最近有效状态。
- 设置与案件进度分开保存，重置案件不清除无障碍设置。

### 8.12 开发者标注模式

仅在开发环境和明确的 authoring 开关下启用：

- 加载 GLB 并显示模型局部坐标。
- 点击表面创建球形或盒形判定区域。
- 调整位置、旋转、尺寸、法线和观察角度阈值。
- 选择所需调查工具、停留时间和前置线索。
- 即时模拟玩家发现条件。
- 编辑标题、描述、标签和提示文本。
- 导出符合案件数据协议的 JSON 片段。

这不是第一版的公众案件编辑器，不包含账号、上传、发布或审核。

## 9. 视觉与声音

### 9.1 视觉原则

- 风格为冷峻、克制的数字物证终端。
- 以暗色背景、低饱和界面和高对比扫描色为主。
- 物证主要使用石膏、黏土、线框、法线或扫描材质。
- 不依赖原始生成纹理；纹理只作为可选辅助层。
- 不把所有内容做成同一种发光玻璃效果，信息层级优先。
- 扫描缺口或模型瑕疵可以被叙事化，但不能影响关键线索判读。

### 9.2 动效原则

- 工具切换、线索确认和推理连线应有短促明确反馈。
- 支持 `prefers-reduced-motion`，减少镜头移动、闪烁和扫描动画。
- 禁止长时间不可跳过的界面动画。

### 9.3 声音原则

- 第一版使用环境底噪、设备反馈和关键发现音效。
- 不强制配音；若有语音必须提供完整字幕。
- 提供独立的主音量、环境音和效果音控制。
- 静音状态下所有信息仍然完整。

## 10. 可访问性

- 所有关键状态不能只通过颜色表达，需配合图标、文字或纹理。
- UI 文本满足合理对比度，支持 100%～150% 缩放。
- 主要功能支持键盘访问和可见焦点。
- 调查工具提供名称、图标和文字说明。
- 支持减少动态效果、关闭闪烁和关闭屏幕震动。
- 计时只用于评级低权重计算，不限制玩家完成案件。
- 首发语言为简体中文，但所有游戏文案通过稳定文本键读取，为后续 `en-US` 预留。

## 11. 性能预算

```text
首屏核心资源：目标小于 5 MB（不含按需物证）
单件发布 GLB：建议小于 10 MB
三件物证资源总量：建议小于 30 MB
同时驻留高精度物证：1 件
桌面目标帧率：60 FPS
低配可接受下限：持续不低于 30 FPS
首次可交互：目标 5 秒内
物证切换：缓存命中 1 秒内，首次加载提供明确进度
```

## 12. 内容与数据原则

- 案件事实必须先于实现冻结，避免为已有模型强行扭曲逻辑。
- 每条必需结论至少由两条独立信息支持。
- 不使用只能凭作者常识才能理解的谜题。
- 关键线索不得依赖低清屏幕难以分辨的单个像素。
- 线索、证词、提示和结论使用稳定 ID，不依赖显示文案作为逻辑键。
- 正式案件 JSON 必须通过 schema 验证才能构建发布。


## 14. 验收标准

### 14.1 必须通过

- 三件 GLB 可分别加载、旋转、缩放、复位和卸载。
- 五种调查工具均至少参与一条线索的实际判定。
- 所有核心线索都能通过可重复的条件触发。
- 推理板能够构建、保存、恢复并验证完整证据链。
- 使用所有第三级提示的玩家仍然可以完成案件。
- 刷新浏览器后恢复到最近进度。
- 无 WebGL、模型 404、JSON 无效和存档损坏均有可理解的错误页面或降级路径。
- 正式构建中无法通过普通 UI 打开开发者标注模式。
- 首发案件从开始到结案不存在未实现占位步骤。

### 14.2 可延后

- 配音。
- 移动端精细适配。
- 游戏手柄支持。
- 云端匿名分析。
- 案件成就和分享卡片。
- 正式公众案件编辑器。

## 15. 里程碑

### M0：交互验证

- 一个占位 GLB。
- 基础旋转、缩放、工具切换。
- 一个隐藏热点和一次线索确认。
